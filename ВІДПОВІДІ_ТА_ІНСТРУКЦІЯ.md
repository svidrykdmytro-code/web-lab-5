## Питання для самоконтролю (Частина 1)
1. **JavaScript** — мова програмування для веб, що виконується в браузері (і на сервері через Node.js). Використовується для інтерактивності сторінок, роботи з DOM, запитів до серверів, односторінкових застосунків, серверної логіки.
2. **ECMAScript** — специфікація (стандарт) мови, а **JavaScript** — її найпоширеніша реалізація, що додає API середовища (DOM, fetch, window тощо).
3. Підключення: inline-атрибути (`onclick="..."`), тег `<script>...</script>` у HTML, зовнішній файл `<script src="script.js"></script>` (з `defer`/`async` за потреби).
4. Змінні: `let` (блокова область видимості), `const` (незмінне посилання), `var` (застарілий, функціональна область видимості).
5. Примітивні типи: `string`, `number`, `bigint`, `boolean`, `undefined`, `null`, `symbol`. Складний тип: `object` (масиви, функції, дати тощо).
6. `undefined` — змінній не присвоєно значення; `null` — явно задане «порожнє» значення, яке призначає розробник.
7. Оператор `typeof x`; для масивів — `Array.isArray(x)`; для `null` — `x === null` (бо `typeof null === "object"`).
8. Бажано строге порівняння `===` / `!==` (без приведення типів). `==` приводить типи (`"5" == 5` → true), тому його уникають.
9. Тернарний оператор: `умова ? значення1 : значення2`. Напр.: `const theme = hour >= 7 && hour < 21 ? "light" : "dark";`
10. `if / else if / else`, `switch`, тернарний оператор, логічні `&&`, `||`, `??`.
11. `for` (відома кількість ітерацій), `while` (умова перевіряється перед тілом), `do...while` (тіло виконається щонайменше раз), `for...of` (значення ітерованих об'єктів), `for...in` (ключі об'єкта).
12. `break` — повністю виходить із циклу (або switch); `continue` — пропускає поточну ітерацію й переходить до наступної.

## Питання для самоконтролю (React)
1. Отримання даних — це побічний ефект (запит до мережі), який не можна виконувати прямо в тілі компонента, бо він запускався б при кожному рендері. `useEffect` виконує його після рендеру в контрольований момент.
2. `[]` — ефект виконується лише один раз після першого рендеру (монтування). Без масиву — після кожного рендеру; `[prop]` — коли змінюється `prop`.
3. Звичайна змінна скидається при кожному рендері, а її зміна не запускає перемальовування. `useState` зберігає значення між рендерами, а виклик `setState` повідомляє React перемалювати компонент з новими даними.
4. Зберегти прапорець у `sessionStorage` (або `localStorage`, якщо потрібно між сесіями) при закритті й перевіряти його в `useEffect` перед запуском `setTimeout`. Так зроблено в `ContactForm.jsx`.
5. Пряма робота з DOM (`document.getElementById`) — імперативна: ми самі описуємо, *як* змінити елементи крок за кроком. React — декларативний: ми описуємо, *що* має відображатися для поточного стану, а React сам оновлює DOM через віртуальний DOM. Це зменшує кількість помилок і спрощує підтримку.
